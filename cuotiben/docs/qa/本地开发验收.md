# 小逗号 H5 本地验收

2026 年 11 月 19 日。入口为 [本机错题本](http://localhost:43872/)。以下流程使用独立浏览器，用户设备上的家庭题目未参与测试。

本轮端到端在家庭开发入口及本地生产构建运行。照片由豆包实时识别，默认讲解走豆包，可选模型走 Requesty。验收程序使用公开原卷，网页初始是空本。精简流程后的构建入口 gzip 82.69 kB。

## 移动端错题目录

本地 Chromium 打开真实空本时只展示三栏订正状态与录题入口。用公开数学题和英语题分别通过豆包、GPT 生成后收录。两道题按真实返回归入数学、英语。数学题直接重做，自评做对后，“数学”筛选下计数为 1／0／1。选“英语＋已订正”为空，可回到全部错题。使用同一批真实记录检查旧数据缺少学科、补分类与刷新。手机 320、390 像素宽和平板 810 像素宽均无横向溢出，三个状态各至少 90 像素宽、44 像素高；学科位于下一行。减少动态效果时不请求开场动画。[空本](手机首页.png) · [两科错题与订正状态](手机错题目录.png)

## 真实 SSE 讲解

在本地 H5 的 390 × 844 浏览器视口，对同一道公开数学题连续测试五个模型。计时从提交操作开始，首段取浏览器实际显示提示文字的时刻，完成取完整讲解可交互的时刻。更新次数统计提示正文的可见变化，浏览器可能合并同一帧到达的多个数据包。这是单题单次记录。

| GPT-5.6 Sol | 3.41 秒 | 5.42 秒 | 13 |

## 精简后的操作实测

- 用公开数学卷第 6 题的单题图片，从空本开始记录页面点击。依次为「录题 → 从相册选 → 识别整张图 → 确认并解析 → 加入错题本」，共 5 次。系统文件选择动作另计，期间画框 0 次，保存后直接回列表。真实豆包给出的结论包含 764。
- 同页第 4、5、6 题只取一次图。保存前两题时直接「收录并圈下一题」，第三题直接入本回列表。刷新后核对三题各自的图片指纹、模型与答案。对同一选区返回核对不重复上传；断网时可重新识别或对照图片补录。
- 在本地 Chromium 中分别对同一张公开原卷第 6 题图片做真实识别，比较改版前后的核对页。在 320 × 568 视口，解析按钮下沿由距顶部 805 像素移至 440 像素；390 × 844 视口由 785 移至 407 像素。两次均为无附加作答的短题，无需滚动即可继续。截图及数值对应此次识别结果，长题和需人工核对的内容按实际长度排版。
- 核对页默认展示排版后的题目。原图折叠，点「修改题目」原位编辑。粘贴含公式的整道题同样直接排版；测试切回编辑核对字符。纸上重做点一次即可对照，最后提交自评才计数。
- 本轮使用本地生产构建和独立 Chromium 浏览器。手机、平板尺寸覆盖与此前真机记录分开计算；系统拍照及 iPhone Safari 留待实机验证。[公式核对页](公式核对.png) · [同页继续圈题](同页继续圈题.png)

## 用户能完成的事

| 任务 | 如何验 | 实际结果 |
| --- | --- | --- |
| A／B 录入、核对 | 输入香港考评局语数英三科各三题。两道有独立编号、独立参考答案的粘贴文本分别选题。再用带共用材料的文本检查人工核对分支。 | 正文和老师答案分别保留。选择继续编辑后仍能从原光标位置输入。 |
| B／C 同页三题 | 在家庭入口与本地生产构建，选一次数学原卷，框第 4、5、6 题，依次核对题干、符号和选项，调用默认豆包讲解再收录。 | 真实识别三次，计数从一变到三。数学公式呈现可读排版并保留 MathML。断网后保留框选，联网重试成功。刷新后核对三份选区的指纹均不同，三个最终答案与原卷评分相符。[原始识别与计时](同页三题实测.json) |
| C 根据原作答给提示 | 使用美国马萨诸塞州教育部门公开的四年级数学第 14 题匿名作答。B 只有最终答案；C 留有乘法和加法过程。豆包和 GPT 分别讲解两问。 | 两个模型对 B 都追问答案是怎样得出的。对 C，豆包引用原式 30 × 3，GPT 同时指出换算后加 45 的思路合理，两者均追问一小时对应多少分钟。[本轮首条提示原文](真题首条提示.json) 只检验这两份作答，孩子能否接着写需家庭试用。[官方原卷及学生作答，第 7 页](https://www.doe.mass.edu/mcas/student/2025/grade4/math-q14.pdf) |
| D 收录、复习、订正 | 对真实生成结果主动收录，在原题独立重做一次并自评做对，再次订正并选择还要再练。取消移除、确认移除、刷新核对。 | 待订正和已订正随最后一次自评变化，订正保留两次、做对一次。放弃移除时题目保留，确认移除后刷新仍少一道。 |
| E 动效 | 收录成功后检查实际加载的 SVG 动画，对订正设置系统减少动态效果后再提交。 | 正常播放一次，减少动态效果时直接显示对应静帧。三支动效均可从源稿重生成。[正常速度、半速和静帧对照](三支动效校对.mp4) |
| F01 失败及并发 | 浏览器真实断网、重新联网、取消正在进行的真实请求、双页签并发、重复保存、真实浏览器容量耗尽。 | 草稿可继续；旧请求不会替换当前页面；重复操作只记一次；容量不足不增加题数，恢复容量后重新写入成功。 |
| M 默认来源与切换 | 经 localhost 和 IP 两种本地地址分别核对来源校验，在平板相同的 localhost 地址用独立浏览器生成第 4 题。四个候选模型分别回答相同的九道真题。 | localhost 默认豆包返回提示与完整答案 835。其他模型的准确率、时延、失败及重测见[逐题模型验收](模型验收.md)。 |

在线服务在连续复验中出现过限流与识别超时，界面停在原题，并显示重试入口。模型耗时包含网络和服务端等待。自动化验收通过界面按钮重试，记录在对应题目上。家长确认前可取消发送，相同选区返回核对页可以沿用已有识别；改圈另一道后重新识别。

## 老师消息和漏图补全

公开数学卷第 14 题要求看阴影图。只粘贴问题时，网页指出缺少阴影范围和总份数。转去选图再取消，原文仍在。把原卷实际显示的「平均分成 8 份、其中 5 份涂色」补入同一题后，默认豆包给出 5/8。保留原文换行进行签名与提交，避免浏览器表单的换行编码导致多行题干被服务判为另一道题。[原卷，第 6 页](https://www.bca.hkeaa.edu.hk/web/Common/res/2024priPaper/P3Math/TSA2024_3MC1.pdf#page=6)

## 本机能保存多少题

此次三个简单印刷题的 JPEG 选区、真实讲解、题干及摘要合计每题约 5.7 至 12.1 KiB，去掉图片后约 2 KiB。若实际留给本站 100 MiB，按三题中最大一题的体积约为 8,400 道，尚未扣除数据库开销、订正历史和空间余量。密集手写或大图会改变这个量级。首页可查看浏览器实时估算的本站用量和额度。

## 性能和覆盖范围

生产构建在本地 Chromium 以 390 × 844 视口、4 Mbps 下行和 150 ms 延迟冷开十次。长列表使用独立数据库，重复使用有出处的原卷、图片及实际模型结果填满 300 条以测读取成本，十次打开列表，三十次切换筛选。新版首屏最大内容绘制 p75 为 520 ms，布局偏移最大 0，300 条题目打开 p75 为 74 ms，筛选 p75 为 26 ms。普通模式按需加载开场动画；空本冷开不请求公式库和三支业务反馈动画。有题时，列表也能直接显示识别出的数学公式。[逐次计时与网络记录](本地性能数据.json)

检查 320 和 390 像素手机、810 像素竖屏及 1143 × 548 横屏布局。荣耀 ELN-W09 真机上，从首页点拍照圈题，读取 2911 × 4117 的公开原卷，实际触控框选第 4 题，豆包识别出三个正确的加数，GPT 给出 835。成功收录后纸上重做、自评做对一次。样本通过浏览器文件输入控件载入，相机系统权限弹窗、iPhone Safari 真机和亲子教学效果仍待验证。单次拖框的帧时间仅供回归，长时间缩放和软键盘体验仍需现场测量。[真机步骤、识别原文与自评次数](荣耀平板实测.json)本轮验收在本地完成，Vercel 线上来源、凭据和试用访问仍需在发布时核对。

## 本地复验

先按项目 README 准备公开试卷、评分资料及本地服务。脚本读取 SHITI_PAPERS 中的原卷及 cases.json。存储和性能脚本还读取 SHITI_RESULTS 中先前真实分析的输出。给浏览器验收脚本设置 SHITI_GALLERY_DIR 可另存手机及平板每一步的截图。设置 PUPPETEER_MODULE 与 CHROME_PATH 可以使用本机已有的浏览器工具。

```sh
SHITI_ORIGIN=http://localhost:43872 node scripts/stream-acceptance.cjs
SHITI_VERIFY_CANCEL=1 node scripts/stream-acceptance.cjs doubao openai/gpt-5.6-sol
SHITI_ORIGIN=http://localhost:43872 node scripts/library-acceptance.cjs
SHITI_ORIGIN=http://localhost:43872 node scripts/direct-acceptance.cjs
SHITI_ORIGIN=http://localhost:43872 node scripts/browser-acceptance.cjs
node scripts/storage-acceptance.cjs
SHITI_ORIGIN=http://localhost:43872 node scripts/text-acceptance.cjs
SHITI_ORIGIN=http://localhost:43872 node scripts/reframe-acceptance.cjs
SHITI_ORIGIN=http://localhost:43872 SHITI_REPORT=/tmp/photo-results.json node scripts/photo-acceptance.cjs
npm run build
SHITI_REPORT=/tmp/performance.json node scripts/performance.cjs
```
