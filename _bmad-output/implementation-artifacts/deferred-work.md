# Deferred Work

## 真实 SSE 传输时序证据

- 当前真实用户脚本会校验多个 `message.delta` 事件，但读取响应时仍在客户端聚合完整 body 后解析；它能证明服务返回了多个 SSE 事件，不能独立证明每个网络分片到达浏览器的真实时间间隔。
- 这是测试证据强度问题，不影响当前页面的实时流式实现。后续若做性能专项，应改成 `ReadableStream.getReader()` 逐块记录首字时间、分片数和分片间隔。

## SSE 边界格式

- 当前供应商解析器覆盖标准单行 `data:` 事件、空响应、提前 EOF、长度截断和非 JSON 代理错误。
- 尚未扩展到少数代理可能发送的多行 `data:` 事件。只有供应商或网关实际采用该格式时再实现，避免为未出现的协议变体扩大当前修复范围。

## 全局样式文件体量

- `app/globals.css` 在本阶段前已经超过 800 行，首页、对话、板书和动效规则混在同一文件，继续扩展会提高视觉回归和冲突概率。
- 本阶段没有改变全局样式加载方式；后续应按页面域拆成首页、对话、板书三个样式模块，并保持现有选择器和视觉不变，作为独立的低风险整理任务。

## 非数理化题目的全链路入口

- 板书协议和内容编排已经支持语言、人文结构，但项目现有识题与课程分析主链路仍只接受数学、物理、化学；真实用户目前不能从首页完成语文、英语、历史等学科的完整流程。
- 这是本阶段之前就存在的产品范围限制。要真正开放，需要同时扩展识别门禁、学科类型、知识节点生成与各学科验收集，属于中等以上范围，不应混进板书内容重构。

## 依赖锁文件重整

- 本次串题修复开始前，为修复 npm 11 无法安装依赖的问题，`package-lock.json` 已产生可选依赖节点与 peer 元数据重写，并混入 `registry.npmmirror.com` 来源。
- 该变更不属于串题修复。后续应使用项目约定的 npm 版本与 registry 单独重建并验证锁文件，避免把供应链来源整理混入功能补丁。
