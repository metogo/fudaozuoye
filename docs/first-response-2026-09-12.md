# 首段返回速度优化验收

## 本轮实际改变

仅调整需要配图的首讲等待链路。原来等“图文核验＋完整求解”全部完成才开始讲；现在同一次模型请求先输出并校验完整图中证据，再继续求解，同时开始首讲。
没有增加正常路径的模型调用，没有换模型、降低置信度门槛或删减推导。纯文字及纯文字截图仍用原来的并行流程。

首讲可以提前流式显示，但 `message.complete`、签名学习状态与下一步作答入口必须等完整分析通过才发布。证据不完整、置信度不足、用户确认的条件被改写、最终证据与提前证据冲突时拒绝放行。断流仍失败，不把部分结果当成完整答案。结构纠正最多一次，和原请求共享 60 秒预算，不能靠重试改变已经发布的事实。

将首轮准备和回合输出辅助函数拆出，避免继续扩张原本过大的路由和适配器文件；两个主文件均恢复到 700 行以内。

## 真实模型对照

使用三张自行绘制的确定性测试图。下面从“已识别题目开始图文分析”计时，不含上传及 OCR。交替测试顺序以减少固定预热偏差，但每个场景各一次，不能用于承诺平均值或 P95。

| 题目 | 原链路到首段 | 新链路到首段 |
| --- | ---: | ---: |
| 3、4 直角边求斜边 | 12.43 秒 | 16.06 秒（变慢） |
| 速度—时间图像求位移 | 25.08 秒 | 13.39 秒 |
| L 形地块面积 | 13.89 秒 | 7.24 秒 |

三题人工检查图中条件、答案和首讲：斜边 5 cm、位移 20 m、面积 84 平方米均正确；没有在首讲公布最终答案。三角形样例反向结果保留，不删失败样例、不宣称每题都更快。数据支持“能提前开始、部分题受益”，不足以支持稳定加速比。

## 完整本地 HTTP 链路

实际经过照片识别、会话准备、首轮请求和状态提交，不使用统计入口、不写生产数据：

- L 形图片：识别 7.70 秒；从提交到正文 18.28 秒；其中图文核验 8.43 秒、核验后模型首字 1.50 秒。完整回合约 25.43 秒。
- 纯文字截图：识别 4.59 秒；从提交到正文 6.63 秒；讲解模型首字 1.38 秒。完整回合约 12.01 秒。

这说明用户提到的七八秒可能包含识别等待。本次优化不消除 OCR 延迟，不能把“识别后首讲更早”当成“首页整体已经降到固定秒数”。已增加 `visual_audited` / `tutor_first_text` 分段事件，配合原有识别耗时事件定位后续慢请求。
测试脚本首次对纯文字截图误用了缺少图片的 multipart 请求，修正为与前端一致的 JSON 请求后复测通过；不是修改产品来适配错误脚本。

## 验证

- 164 个测试文件、1,593 条测试通过，行覆盖率 96.59%，分支覆盖率 84.54%。
- 新增覆盖：跨字符分片的完整证据观察、双协议流式请求、置信度与用户修正条件、结构纠正、冲突/断流拒绝、提前正文不提前放行、后台失败取消。
- 类型检查、lint、API 编译、生产构建、差异检查通过。
- 10 条跨学科隔离浏览器流程，以及移动/桌面公式、复制、引用、图谱拖拽、练习、导出和返回滚动回归通过。
- 首页资源预算保持通过：JS 798,970 B、gzip 246,977 B、CSS 141,377 B。

复现脚本：`scripts/visual-first-response-qa.mjs`（需要现有模型配置；生成图后做新旧对照）；`scripts/visual-intake-http-qa.mjs`（需要本地 API 已启动，使用前一个脚本生成的 L 形图片）。原始合成测试结果在 `outputs/visual-first-response/`，不包含凭据或用户图片。

## 限制

未做生产并发压测、真实手机网络对照或足够样本的统计检验。大幅缩短 OCR 本身还需独立实测；本轮没有冒险更换识别模型、压低图片质量或删掉识别校验。
改动仅在本地，未提交、推送或部署。
