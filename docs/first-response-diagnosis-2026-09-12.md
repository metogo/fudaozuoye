# 对话首段等待诊断

## 范围与结论

针对“之前约 4 秒，现在约 8 秒”的反馈，只诊断，不修改产品实现、模型、生产配置或部署。使用本地真实页面、真实模型、同一张合成纯文字题图，独立 Chrome 上下文；拦截统计请求，不写共享计数。

当前长等待主要在识图：必须拿到完整题文及识别校验结果后才能启动首讲。尚无用户历史 4 秒请求的分段记录，因此不能确认是哪次提交造成翻倍，也不能把模型供应商排队或知识图谱竞争当成已证实根因。

## 完整页面对照

按开启、关闭、关闭、开启的顺序，在测试浏览器中拦截知识图谱请求。关闭不是产品改动，不模拟成功。

| 图谱 | 提交到首段 30 字可见 | 提交到首讲请求发出 |
| --- | ---: | ---: |
| 开启 | 7.674 秒 | 4.856 秒 |
| 关闭 | 6.986 秒 | 4.515 秒 |
| 关闭 | 5.923 秒 | 3.775 秒 |
| 开启 | 6.373 秒 | 4.094 秒 |

图谱请求在首讲请求后约 0.31 秒发出。当前首讲、后台求解及图谱规划确实并发；早期版本只在用户打开图谱后加载。上述小样本不支持“图谱使首讲多等固定 4 秒”的判断，也不能排除高负载下竞争。首次诊断用 Playwright response.text 读取 SSE 失败，不能依赖该字段推断服务端阶段；表中浏览器请求时间与 DOM 可见时间有效。

随后改用浏览器 fetch.clone 分流读取阶段事件，未缓存或阻塞原响应，补测两次：

| 图谱 | 识别接口耗时 | 首讲模型首字耗时 | 首个模型片段到达（自提交） | 正文 30 字可见（自提交） |
| --- | ---: | ---: | ---: | ---: |
| 关闭 | 10.144 秒 | 1.053 秒 | 11.308 秒 | 12.017 秒 |
| 开启 | 5.668 秒 | 1.336 秒 | 7.116 秒 | 7.683 秒 |

识别返回 related=false，未走配图复核流程。识别后的会话准备阶段耗时 0 毫秒（服务端记录精度）。30 字可见不是首字，差值包含继续生成这 30 字和浏览器检测开销，不能全算作前端渲染延迟。

这两次首字阶段事件与文本到达同一时刻，没有发现模型片段被客户端额外扣留数秒。六次页面均无 pageerror，首讲正常完成。原始证据在 outputs/first-response-diagnosis/browser.json 与 browser-pair.json。

## 对之前优化的校正

- 上次主要优化“需要配图”的图文复核与完整求解等待，纯文字截图并不经过这条路径，不能据此宣称该类首页等待已经改善。
- 上次真实模型 API 测试没有触发实际页面的自动图谱请求，不能替代完整页面的并发性能验收。本次已补上，但仍非生产并发压测。
- 当前识图非流式请求输出完整题文、学科学段、学生作答、配图关系及缺失条件，再经校验发布；这是首讲之前的串行阶段。优化优先关注该阶段，而非 loading 动画或降低首讲质量。
- 客户端正文批处理间隔为 40 毫秒，等待骨架没有固定数秒定时器；输出长度上限并非本次首字等待的证据。

## 限制及下一步

没有历史同题同模型分段基线，没有供应商排队、重试与 token 明细，不能把识别内部的十秒进一步归因到某个环节。本次六次合成截图测试不能代表所有题、所有网络与线上可用率。

后续如授权优化，应以完整页面提交到首段正文为主指标，同时记录识别和首字分段，针对识别输出协议及请求耗时做同题对照，不删可靠性检查、不降图片清晰度、不降低置信度门槛。改动量级预计中等，主要风险是提速造成漏题设，需以识别准确性回归守住边界。

复现：本地 3000 / 9000 服务正常时执行 node scripts/diagnose-first-response.mjs；--pair 运行附带分段记录的两次对照。实际调用模型；脚本拦截统计。未提交、推送、部署。
